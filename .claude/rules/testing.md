# テスト・品質保証の方針

## 品質ゲート
- 入口は `python scripts/check.py [all|backend|frontend]` の 1 つだけ。人・Stop Hook・CI が同じコマンドを使う。
  終了コードは 0 = 成功、1 = チェック失敗、2 = 環境不備。
- チェックを追加するときは `scripts/check.py` に追加する。Hook や CI に直接コマンドを書かない。

## テストの書き方（pytest）
- 経路計算は純粋関数として、手で作った小さなポート一覧のフィクスチャで検証する。
  確認すること：最小所要時間の組み合わせを選ぶこと、貸出不可・返却不可のポートを除外すること、徒歩のみのほうが速いケース、候補が 0 件のケース。
- GBFS の取得は、`backend/tests/fixtures/` に置いた実データの縮小版 JSON を使ってテストする。
  **テストから実ネットワークに接続しない。**
- GBFS 取得失敗（タイムアウト・不正な JSON・HTTP 5xx）のときに 503 を返し、ダミー値を返さないことを必ずテストする。
- Lambda 経路（Mangum + HTTP API v2 イベント）の疎通テストを最低 1 本残す。

## 禁止事項
- 失敗しているテストを、削除・`skip`・期待値の書き換えで通すこと。仕様が変わった場合は、その理由をコミットメッセージに書く。
- テストのために本番コードへテスト専用の分岐を入れること。

## 評価駆動
- 経路品質の評価には、代表的な地点ペア（例：梅田→難波、大阪城→天王寺）の期待値を表にしたテストを使う。
  ロジックを変えたら結果の差分を確認する。
